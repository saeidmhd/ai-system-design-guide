## مبانی توجه

### ایده اصلی

توجه به هر موقعیت در یک توالی اجازه می‌دهد تا اطلاعات را از تمام موقعیت‌های دیگر جمع‌آوری کند. برخلاف بازگشت (Recurrence) که اطلاعات را گام‌به‌گام منتقل می‌کند، توجه ارتباطات مستقیمی ایجاد می‌نماید.

**مدل ذهنی برای مهندسان سیستم‌های توزیع‌شده:**
- شبکه RNN: ارسال پیام در امتداد یک زنجیره (Message passing along a chain)
- توجه (Attention): الگوی انتشار/اشتراک (Pub/sub) که در آن هر نود می‌تواند از تمام نودهای دیگر پرس‌وجو کند

### چارچوب پرس‌وجو، کلید و مقدار (Query, Key, Value)

توجه از سه تصویرسازی خطی (Projection) از ورودی استفاده می‌کند:

| مؤلفه | نقش | تمثیل |
|-------|-----|-------|
| پرس‌وجو یا Query (Q) | به دنبال چه چیزی هستم؟ | پرس‌وجوی جستجو (Search query) |
| کلید یا Key (K) | چه چیزی در بر دارم؟ | نمایه یا ایندکس سند (Document index) |
| مقدار یا Value (V) | چه چیزی ارائه می‌دهم؟ | محتوای سند (Document content) |

<div dir="ltr">

```python
# Input: x of shape [batch, seq_len, d_model]

Q = x @ W_q  # [batch, seq_len, d_k]
K = x @ W_k  # [batch, seq_len, d_k]
V = x @ W_v  # [batch, seq_len, d_v]
```

</div>

## توجه ضرب نقطه‌ای مقیاس‌شده (Scaled Dot-Product Attention)

عملیات بنیادین توجه:

<div dir="ltr">

```python
def scaled_dot_product_attention(Q, K, V, mask=None):
    d_k = Q.shape[-1]
    
    # Compute attention scores
    scores = Q @ K.transpose(-2, -1)  # [batch, seq_len, seq_len]
    scores = scores / math.sqrt(d_k)  # Scale
    
    # Apply mask (for causal attention)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))
    
    # Convert to probabilities
    attention_weights = F.softmax(scores, dim=-1)
    
    # Weighted sum of values
    output = attention_weights @ V
    
    return output, attention_weights
```

</div>

### چرا مقیاس‌بندی با جذر d_k انجام می‌شود؟

**محبوب در مصاحبه‌ها**: این سوال شهود عددی (Numerical intuition) شما را می‌سنجد.

بدون مقیاس‌بندی، ضرب‌های نقطه‌ای با افزایش بعد بزرگ‌تر می‌شوند:
- برای q و k با بعد d که مؤلفه‌های آن‌ها مستقل، با میانگین صفر و واریانس یک هستند:
- امید ریاضی E[q . k] = 0، اما Var[q . k] = d
- انحراف معیار = sqrt(d)

هنگامی که d بزرگ باشد (۵۱۲ یا بیشتر)، مقادیر حاصل از ضرب نقطه‌ای می‌توانند بسیار بزرگ یا بسیار کوچک شوند. اعمال Softmax بر روی مقادیر بزرگ به توزیع وان-هات (one-hot) نزدیک می‌شود که به ناپدید شدن گرادیان (vanishing gradients) می‌انجامد.

<div dir="ltr">

```python
# Demonstration
import numpy as np

d = 512
q = np.random.randn(d)
k = np.random.randn(d)

unscaled = np.dot(q, k)      # Magnitude ~ sqrt(512) ~ 22
scaled = unscaled / np.sqrt(d)  # Magnitude ~ 1
```

</div>

### ماسک‌گذاری علی (Causal Masking)

برای تولید خودبازگشتی (Autoregressive generation)، هر موقعیت تنها می‌تواند به موقعیت‌های قبلی توجه کند:

<div dir="ltr">

```python
def create_causal_mask(seq_len):
    # Lower triangular matrix
    mask = torch.tril(torch.ones(seq_len, seq_len))
    return mask

# Example for seq_len=4:
# [[1, 0, 0, 0],
#  [1, 1, 0, 0],
#  [1, 1, 1, 0],
#  [1, 1, 1, 1]]
```

</div>

موقعیت‌هایی با mask=0 امتیاز منفی بی‌نهایت (negative infinity) دریافت می‌کنند که پس از اعمال softmax به ۰ تبدیل می‌شوند.

## توجه چند سر (Multi-Head Attention)

به جای یک تابع توجه واحد، از چندین «سر» (Heads) استفاده می‌شود که به جنبه‌های متفاوتی توجه می‌کنند:

<div dir="ltr">

```python
class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, num_heads):
        super().__init__()
        self.num_heads = num_heads
        self.d_k = d_model // num_heads
        
        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)
    
    def forward(self, x, mask=None):
        batch_size, seq_len, d_model = x.shape
        
        # Project to Q, K, V
        Q = self.W_q(x)  # [batch, seq_len, d_model]
        K = self.W_k(x)
        V = self.W_v(x)
        
        # Reshape to multiple heads
        Q = Q.view(batch_size, seq_len, self.num_heads, self.d_k).transpose(1, 2)
        K = K.view(batch_size, seq_len, self.num_heads, self.d_k).transpose(1, 2)
        V = V.view(batch_size, seq_len, self.num_heads, self.d_k).transpose(1, 2)
        # Now: [batch, num_heads, seq_len, d_k]
        
        # Attention per head
        attn_output, _ = scaled_dot_product_attention(Q, K, V, mask)
        
        # Concatenate heads
        attn_output = attn_output.transpose(1, 2).contiguous()
        attn_output = attn_output.view(batch_size, seq_len, d_model)
        
        # Final projection
        output = self.W_o(attn_output)
        return output
```

</div>

**چرا سرهای متعدد؟**
۱. سرهای مختلف الگوهای گوناگونی را می‌آموزند (نحو، معناشناسی، هم‌مرجعی یا coreference)
۲. تنوع بازنمایی (اثر تجمیعی یا ensemble effect) فراهم می‌کند
۳. امکان محاسبات موازی را در میان سرها فراهم می‌سازد

### الگوهای تعداد سرها (Head Count Patterns)

| مدل | d_model | سرها (Heads) | بُعد d_k به ازای هر سر |
|-----|---------|--------------|-------------------|
| BERT-base | 768 | 12 | 64 |
| GPT-2 | 768 | 12 | 64 |
| GPT-3 175B | 12288 | 96 | 128 |
| Llama 2 70B | 8192 | 64 | 128 |

مقدار d_k برابر با ۶۴ یا ۱۲۸ در ابعاد و اندازه‌های مختلف مدل‌ها به شکلی چشمگیر ثابت و یکنواخت است.

## الگوهای توجه (Attention Patterns)

### توجه چه چیزی را یاد می‌گیرد

سرهای مختلف در الگوهای متفاوتی تخصص می‌یابند:

| نوع الگو | آنچه ضبط می‌کند | مثال |
|----------|-----------------|------|
| موقعیتی (Positional) | واحدهای Token مجاور | کلمه بعدی/قبلی |
| نحوی (Syntactic) | روابط گرامری | فاعل-فعل |
| معنایی (Semantic) | روابط معنایی | هم‌مرجعی (Coreference) |
| جداکننده (Delimiter) | علائم نگارشی، ساختار | مرزهای بخش‌ها (Section boundaries) |
| نادر (Rare) | الگوهای کم‌تکرار | کپی کردن کلمات نادر |

### مصورسازی توجه

وزن‌های توجه را می‌توان به صورت نقشه‌های حرارتی (Heatmaps) مصورسازی کرد که نشان می‌دهند کدام موقعیت‌ها به کدام موقعیت‌ها توجه دارند:

<div dir="ltr">

```
Query positions (rows) vs Key positions (columns)

"The cat sat on the mat"

         The  cat  sat  on   the  mat
The     [□    ○    ○    ○    ○    ○ ]
cat     [●    □    ○    ○    ○    ○ ]
sat     [○    ●    □    ○    ○    ○ ]
on      [○    ○    ●    □    ○    ○ ]
the     [○    ○    ○    ○    □    ○ ]
mat     [○    ●    ○    ●    ●    □ ]

● = high attention, ○ = low attention
```

</div>

کلمه "mat" به شدت به "cat" (معنایی)، "on" (نحوی) و "the" (حرف تعریف/تعیین‌کننده) توجه می‌کند.

## انواع کارآمد توجه (Efficient Attention Variants)

توجه استاندارد از نظر طول توالی دارای پیچیدگی O(n^2) است. انواع متعددی این پیچیدگی را کاهش می‌دهند:

### توجه تنک (Sparse Attention)

تنها به زیرمجموعه‌ای از موقعیت‌ها توجه می‌شود نه به تمام آن‌ها:

| گونه (Variant) | الگو | پیچیدگی | مثال |
|----------------|------|---------|------|
| محلی (Local) | پنجره‌ای در اطراف هر موقعیت | O(n * w) | Longformer |
| گام‌دار (Strided) | هر k-امین موقعیت | O(n^2 / k) | Sparse Transformer |
| سراسری (Global) | واحدهای Token ویژه به همه جا توجه می‌کنند | O(n * g) | مدل‌های Longformer و BigBird |
| بلوکی (Block) | توجه بلوکی-قطری (Block-diagonal) | O(n * b) | BigBird |

**الگوی Longformer:**

<div dir="ltr">

```
Local window + Global tokens

[G] [L] [L] [L] [L] [G] [L] [L] [L] [L]

G: Global tokens (attend to/from all)
L: Local tokens (attend within window)
```

</div>

### توجه خطی (Linear Attention)

جایگزینی softmax با جایگزین‌های خطی‌پذیر:

<div dir="ltr">

```python
# Standard attention (quadratic)
attention = softmax(Q @ K.T) @ V

# Linear attention approximation
attention = (Q @ (K.T @ V))  # Associativity trick
```

</div>

**گونه‌ها:**
- مدل Performer: تقریب ویژگی‌های تصادفی (Random feature approximation)
- مدل Linear Transformer: `elu(Q) @ (elu(K).T @ V)`
- توجه خطی گیت‌دار یا Gated linear attention (مانند Gated DeltaNet و Kimi Delta Attention): گیت‌های یادگرفته‌شده و به‌روزرسانی حالت مبتنی بر قاعده دلتا (delta-rule) را اضافه می‌کند، و این همان سازوکاری است که مدل‌های ترکیبی (hybrid) در سال ۲۰۲۶ عملاً از آن استفاده می‌کنند

**موازنه و بده‌بستان (Tradeoff):** سرعت بالاتر است اما کیفیت افت می‌کند، به‌ویژه در تسک‌هایی که نیازمند توجه دقیق هستند (بازیابی دقیق یک Token در فواصل دور دست). به همین دلیل است که مدل‌های محیط عملیاتی (production) به جای تکیه انحصاری بر لایه‌های خطی، لایه‌های خطی را به شکل یک‌درمیان با لایه‌های توجه کامل یا تنک ترکیب می‌کنند.

### مقایسه پیچیدگی

| روش | زمان | فضا | کیفیت | توضیحات |
|-----|------|-----|-------|---------|
| استاندارد (Standard) | O(n^2) | O(n^2) | بهترین | مبنا (Baseline) |
| تنک یا Sparse (مدل Longformer) | O(n) | O(n) | نزدیک به بهترین | برای اسناد طولانی |
| خطی یا Linear (مدل Performer) | O(n) | O(n) | افت‌کرده | بهترین برای توالی‌های بسیار طولانی |
| فلش اتنشن (Flash Attention) | O(n^2) | O(n) | بهترین | توجه دقیق، کرنل آگاه از ورودی/خروجی (IO-aware kernel) |
| ترکیبی یا Hybrid (خطی یا SWA + چند لایه کامل/تنک) | غالباً O(n) | غالباً O(n) | نزدیک به بهترین | رایج در مدل‌های پرچمدار متن‌باز سال ۲۰۲۶ |

<a id="hybrid-and-sparse-attention-in-2026-open-models"></a>

### توجه ترکیبی و تنک در مدل‌های متن‌باز سال ۲۰۲۶

انواع مطرح‌شده در بالا دیگر صرفاً موضوعاتی پژوهشی نیستند. پنج انتشار پرچمدار متن‌باز زیر، همگی از اواخر اوت تا سپتامبر ۲۰۲۶، طبق شناسنامه‌های مدل (model cards) خود با طرح‌های غیرمعمول و نوآورانه توجه یا ساختار KV عرضه شده‌اند. البته همه مدل‌ها چنین نیستند: مدل Granite 4.2 از شرکت IBM (انتشار در ۲۵ اوت) یک ترنسفورمر چگال معمولی با ساختار GQA است.

| مدل (تاریخ انتشار) | طرح توجه (Attention scheme) | پیامد بر روی ساختار KV |
|--------------------|-----------------------------|------------------------|
| مدل Qwen3.8-Flash-Next (۲۶ اوت) | توجه خطی Gated DeltaNet در ۳ لایه از هر ۴ لایه، و Qwen Sparse Attention در لایه چهارم | تنها ۱ لایه از هر ۴ لایه یک KV cache در حال رشد را نگه می‌دارد؛ لایه‌های خطی حالتی با اندازه ثابت دارند |
| مدل GLM-5.3-Flash (۲۶ اوت) | مکانیزم Kimi Delta Attention (خطی) در ۳ لایه از هر ۴ لایه، و توجه تنک به سبک DeepSeek بر روی یک متغیر پنهان (latent) MLA در لایه چهارم | حدود ۱ لایه از هر ۴ لایه یک KV cache در حال رشد (فشرده‌شده) نگه می‌دارد؛ Z.ai گزارش می‌دهد که این رویکرد ترکیبی هزینه سرویس‌دهی در زمینه طولانی (long-context) را به شدت کاهش می‌دهد |
| پیش‌نمایش Tencent Hy4 (۲۸ اوت) | مکانیزم Gated DeepSeek Sparse Attention همراه با IndexCache، بر روی کش متغیر پنهان MLA | کش برای هر لایه به ازای هر Token یک متغیر پنهان ۵۱۲ بعدی به همراه یک کلید RoPE با بعد ۶۴ را ذخیره می‌کند؛ هر پرس‌وجو تنها ۲,۰۴۸ کلید برتر انتخاب‌شده خود را می‌خواند |
| مدل DeepSeek V4.1-Flash (۱۰ سپتامبر) | انکودر-دکودر علی (KV سراسری دکودر از حالت‌های انکودر تصویر می‌شود)، Compressed Sparse Attention 2، و ساختار KV اصلی با دقت FP4 | ۸۹۰ بایت از KV سراسری به ازای هر Token؛ طبق گزارش DeepSeek حدود ۴ برابر کمتر از V4-Flash و حدود ۴۳۷ برابر کمتر از DeepSeek-V1 است |
| مدل MiMo-V2.6-Pro (۲۱ سپتامبر) | ۶۰ لایه پنجره لغزان (با پنجره ۱۲۸ تایی از Tokenها) به همراه ۱۰ لایه سراسری | تنها ۱۰ لایه از ۷۰ لایه با طول بافت (context) رشد می‌کنند |

هر پنج مدل از بافت ۱ میلیون Tokenای (1M-token context) پشتیبانی می‌کنند (مدل Qwen3.8-Flash-Next از طریق YaRN از ۲۶۲ هزار بومی ارتقا یافته است).

**تغییرات ناشی از این تحولات در طراحی سیستم:**
- **تعیین اندازه KV مختص هر معماری است.** فرمول `2 x layers x kv_heads x head_dim x bytes` برای GQA به سبک Llama صحیح است (۳۲۰ کیلوبایت به ازای هر Token برای یک مدل 70B)، اما این مدل‌ها را توصیف نمی‌کند: مدل DeepSeek V4.1-Flash مصرف ۸۹۰ بایت KV سراسری به ازای هر Token را گزارش می‌دهد که تقریباً ۳۷۰ برابر کمتر از رقم مربوط به Llama است. این ۸۹۰ بایت تنها کش سراسری را پوشش می‌دهد: شناسنامه مدل همچنین KV با پنجره لغزان (sliding-window KV) را توصیف می‌کند که به جای رشد با بافت، در طول پنجره محدود می‌شود؛ بنابراین این نسبت، رشد در بافت‌های طولانی را توصیف می‌کند، نه کل حافظه کش در یک درخواست کوتاه. بایت‌های KV به ازای هر Token را از روی پیکربندی‌ها (configs) و شناسنامه‌های مدل مقایسه کنید، نه از روی تعداد پارامترها، و بررسی کنید که رقم منتشرشده شامل کدام بخش‌های کش است.
- **توجه تنک داده کمتری می‌خواند؛ اما لزوماً داده کمتری ذخیره نمی‌کند.** طرح‌های مبتنی بر ایندکس‌گذار (Indexer-based) کلیدهای top-k را به ازای هر پرس‌وجو انتخاب می‌کنند که این امر محاسبات و پهنای باند توجه را در بافت‌های طولانی کاهش می‌دهد، اما کش تنها زمانی کوچک‌تر می‌شود که توجه تنک با فشرده‌سازی همراه گردد (یک متغیر پنهان MLA در Hy4، یا KV فشرده‌شده FP4 در V4.1-Flash).
- **قابلیت Prefix caching نیازمند موتورهای آگاه از معماری ترکیبی (Hybrid-aware) است.** لایه‌های خطی و پنجره لغزان دارای وضعیتی (state) هستند که صرفاً یک لیست ساده از KV به ازای هر Token نیست. درخت پیشوندی (Radix tree) آگاه از SWA در فریم‌ورک SGLang نسخه 0.5.20 نرخ اصابت Token (token hit rate) را از ۴۳.۸٪ به ۶۰.۸٪ افزایش داد و میانگین TTFT را از ۱.۵۷ ثانیه به ۱.۰۷ ثانیه روی DeepSeek-V4-Flash با یک Prompt سیستمی مشترک کاهش داد (طبق گزارش SGLang). پیش از آنکه روی صرفه‌جویی حاصل از prefix-cache حساب باز کنید، مطمئن شوید که نسخه موتور شما از چیدمان کش معماری مورد نظر پشتیبانی می‌کند.

<a id="flash-attention"></a>

## فلش اتنشن (Flash Attention)

فلش اتنشن (Flash Attention) یک پیاده‌سازی پیشرفته (state-of-the-art) است که ضمن محاسبه توجه دقیق (exact attention)، به مصرف حافظه با مرتبه O(n) دست می‌یابد.

### مسئله‌ای که حل می‌کند

مکانیزم توجه استاندارد نیازمند مادی‌سازی و شکل‌دهی کامل (materializing) ماتریس توجه n × n در حافظه است:
- به ازای کانتکست 8K: تعداد 64M عدد اعشاری (floats) = ۲۵۶ مگابایت به ازای هر لایه و هر هد
- به ازای کانتکست 100K: تعداد 10B عدد اعشاری = ۴۰ گیگابایت به ازای هر لایه و هر هد

این نیازمندی حافظه، اندازه دسته (batch size) و طول کانتکست (context length) را محدود می‌کند.

### نحوه کارکرد

فلش اتنشن (Flash Attention) برای اجتناب از ذخیره‌سازی ماتریس کامل توجه، از روش کاشی‌کاری (tiling) و محاسبه مجدد (recomputation) استفاده می‌کند:

<div dir="ltr">

```
Standard: Q, K -> Attention Matrix (n x n) -> Output
Flash:    Q, K -> Tiles (block_size x block_size) -> Incremental Output
```

</div>

**ایده‌های کلیدی:**
۱. پردازش توجه در بلوک‌هایی که در حافظه SRAM روی تراشه جای می‌گیرند
۲. عدم مادی‌سازی و ذخیره ماتریس کامل توجه در حافظه HBM در هیچ زمانی
۳. محاسبه مجدد توجه در طول پاس پس‌انتشار (backward pass) که سریع‌تر از بارگذاری مقادیر ذخیره‌شده از HBM است

### مکانیزم FlashAttention-2 (تقسیم کار / Work Partitioning)
با بهبود موازی‌سازی در میان هدها و طول توالی، برای پردازنده‌های A100/H100 بهینه‌سازی شده است.

### مکانیزم FlashAttention-3 (بهینه‌سازی FP8 و H100)
**کرنل استاندارد روی معماری هاپر (Hopper - H100/H200):**
- **اجرای ناهمگام (Asynchronous Execution)**: با استفاده از تخصیص وارپ (warp specialization) و شتاب‌دهنده حافظه تنسور (TMA - Tensor Memory Accelerator)، عملیات GEMM (ضرب ماتریسی) و softmax را با یکدیگر همپوشانی می‌کند.
- **پشتیبانی از FP8**: دستیابی به نزدیک به ۱.۲ فلاپس (1.2 PFLOPS) در FP8 در مقایسه با حداکثر ۷۴۰ ترافلاپس (740 TFLOPS) در FP16 روی H100، با استفاده از کوانتیزاسیون بلوکی (block quantization) و پردازش ناهمدوس (incoherent processing - یک چرخش هادامارد که مقادیر پرت را پخش می‌کند) برای پایین نگه داشتن خطای FP8.
- **افزایش سرعت (Speedup)**: حدود ۱.۵ تا ۲.۰ برابر سریع‌تر از FlashAttention-2 در فرمت FP16 (تمام ارقام گزارش‌شده در مقاله).

### مکانیزم FlashAttention-4 (معماری‌های Hopper و Blackwell)
نسخه FlashAttention-3 فقط معماری Hopper را هدف قرار می‌دهد. **FlashAttention-4** با زبان CuTe DSL نوشته شده است، هر دو معماری Hopper و Blackwell (شامل H100 و B200) را هدف قرار می‌دهد و به صورت پکیج مجزای خود (`flash-attn-4`) عرضه می‌شود که تا سپتامبر ۲۰۲۶ همچنان در نسخه‌های بتای 4.0.0 قرار داشت. موتورهای سرویس‌دهی روی قطعات رده بلک‌ول (Blackwell-class) بک‌اند‌های توجه دیگری (مانند FlashInfer و کرنل‌های اختصاصی ارائه‌دهنده) را نیز ارائه می‌دهند؛ بنابراین پیش از استناد به توان عملیاتی (Throughput) توجه، بررسی کنید که موتور شما عملاً کدام بک‌اند را انتخاب می‌کند.

<a id="multi-head-latent-attention-mla"></a>

## توجه نهفته چند سر (MLA - Multi-head Latent Attention)

معماری **MLA جایگزین مدرن GQA** برای فشارهای شدید روی KV cache است که در DeepSeek-V2 معرفی شد و در V3 نیز به کار گرفته شد.

به جای صرفاً گروه‌بندی هدها، MLA بردارهای Key و Value را پیش از ذخیره در کَش، درون یک **فضای پنهان کم‌بُعد (low-dimensional latent space)** فشرده می‌کند.

<div dir="ltr">

```
Query (Up-projected) ────────┐
                             ▼
Key, Value (Down-projected) ─▶ [Low-dim Latent Cache] ─▶ [Output]
                             ▲
                             └─ Projection Matrices
```

</div>

| معیار | MHA | GQA | MLA |
|--------|-----|-----|-----|
| اندازه KV Cache | ۱۰۰٪ | ۱۲.۵٪ | **چند درصد معدود** (مدل DeepSeek-V2 تعداد ۵۷۶ مقدار به ازای هر Token در هر لایه کَش می‌کند، یعنی حدود ۱.۸٪ روش MHA با ۱۲۸ هد؛ DeepSeek کاهش ۹۳.۳ درصدی کَش را نسبت به مدل متراکم DeepSeek 67B گزارش کرده است) |
| کیفیت | خط مبنا (Baseline) | نزدیک به خط مبنا | **هم‌تراز یا بهتر از MHA در آزمون‌های حذف تجربی (ablations) در DeepSeek** |
| تاخیر (Latency) | خط مبنا (Baseline) | سریع‌تر | **سریع‌ترین در کانتکست‌های طولانی (به دلیل کاهش ورودی/خروجی I/O)** |

**چرا MLA برنده است**: کَش به ازای هر Token یک متغیر پنهان (latent) فشرده‌شده به همراه یک کلید موقعیتی کوچک نگهداری می‌کند. در زمان رمزگشایی (decode time)، ماتریس‌های تصویرسازی رو به بالا (up-projection) درون تصویرسازی‌های کوئری و خروجی ادغام (جذب) می‌شوند؛ بنابراین متغیر پنهان هرگز مجدداً به K و V کامل منبسط نمی‌شود. مکانیزم RoPE مانع این ادغام می‌شد، به همین دلیل MLA از **RoPE مجزاشده (decoupled RoPE)** استفاده می‌کند: مجموعه مجزا و کوچکی از ابعاد چرخشی اطلاعات موقعیت را حمل می‌کنند. نتیجه این طراحی، مصرف پهنای باند حافظه به مراتب کمتر به ازای هر گام رمزگشایی در کانتکست‌های طولانی است.

کاربرد MLA فراتر از DeepSeek گسترش یافت (مدل Kimi K2 از آن استفاده می‌کند، و لایه‌های توجه تنک در Tencent Hy4 و GLM-5.3-Flash مبتنی بر یک متغیر نهفته KV با ۵۱۲ بُعد هستند)، در حالی که خط تولید V4 خود شرکت DeepSeek به سمت رویکرد هیبریدی از «توجه تنک فشرده» و «توجه بسیار فشرده» حرکت کرده است؛ بخش [توجه هیبریدی و تنک در مدل‌های متن‌باز سال ۲۰۲۶](#hybrid-and-sparse-attention-in-2026-open-models) را ببینید.

<a id="kv-cache-optimizations--context-caching"></a>

## بهینه‌سازی‌های KV Cache و Context Caching

### کَش‌سازی کانتکست (Context Caching در سطح سیستم)
ارائه‌دهندگان API (مانند OpenAI، Gemini، Anthropic و DeepSeek) قابلیت **Context Caching** (یا prompt caching) را ارائه می‌دهند.
- **نحوه کارکرد**: تانسورهای KV را برای یک «پیشوند (prefix)» طولانی (مثلاً یک کتاب قانون با 100k تا Token) از پیش محاسبه و ذخیره می‌کند و هنگام رسیدن درخواست‌های بعدی که با همان بایت‌ها آغاز می‌شوند، آن‌ها را مجدداً استفاده می‌نماید.
- **مزیت در تاخیر (Latency)**: مرحله پیش‌تکمیل (Prefill) برای پیشوند کَش‌شده رد می‌شود، بنابراین میزان صرفه‌جویی در زمان تا اولین Token (معیار TTFT) متناسب با میزانی از Prompt است که به اشتراک گذاشته شده است.
- **مزیت در هزینه**: خواندن از کَش در اکثر مدل‌های کنونی OpenAI، Anthropic و Google با تعرفه 0.1x هزینه ورودی محاسبه می‌شود؛ در مدل‌های Claude Opus 5.5، Claude Sonnet 5.5، GPT-6.1 Sol و GPT-6.1 Terra برابر 0.05x، و در Claude Fable 5.1 برابر 0.025x است. سایر ارائه‌دهندگان متفاوت عمل می‌کنند (در Grok 4.7 متعلق به xAI برابر 0.25x و بازدید موفق کَش در DeepSeek V4.1-Flash برابر 0.02x است). نوشتن در کَش هزینه اضافی دارد: ۱.۲۵ برابر (1.25x) برای کَش ۳۰ دقیقه‌ای OpenAI (مدل‌های GPT-5.6 و پس از آن) و کَش ۵ دقیقه‌ای Anthropic؛ ۲ برابر (2x) برای کَش ۱ ساعته Anthropic؛ ۲.۵ برابر (2.5x) برای کَش ۱۲ ساعته OpenAI؛ در مقابل، Google هزینه ذخیره‌سازی صریح در کَش را بر اساس ساعت محاسبه می‌کند (مدل Gemini 4 Argon فقط کَش‌سازی ضمنی را ارائه می‌دهد). برای اطلاع از نرخ‌های فعلی بخش [قیمت‌گذاری و هزینه‌ها](../02-model-landscape/03-pricing-and-costs.md) و برای الگوهای طراحی بخش [KV Cache و Context Caching](../04-inference-optimization/02-kv-cache-and-context-caching.md) را ببینید.

### توجه با پنجره لغزان (SWA - Sliding Window Attention)
توجه یک لایه را به یک پنجره ثابت محدود می‌کند (در Mistral 7B برابر ۴٬۰۹۶ تا Token) تا رشد KV cache آن لایه همراه با کانتکست متوقف شود. مدل‌های مدرن لایه‌های SWA را با چند لایه سراسری (global) ترکیب متناوب می‌کنند تا بازیابی اطلاعات در فواصل دور حفظ شود: مدل Gemma 3 به ازای هر لایه سراسری از پنج لایه محلی استفاده می‌کند، و MiMo-V2.6-Pro از ۶۰ لایه پنجره لغزان (با پنجره ۱۲۸ تایی Token) و ۱۰ لایه سراسری بهره می‌برد.

### توجه چندکوئری (MQA - Multi-Query Attention)

اشتراک‌گذاری یک جفت K و V واحد میان تمام هدهای Query:

<div dir="ltr">

```python
# Standard MHA
Q: [batch, num_heads, seq, d_k]  # 32 heads
K: [batch, num_heads, seq, d_k]  # 32 separate K
V: [batch, num_heads, seq, d_k]  # 32 separate V

# MQA
Q: [batch, num_heads, seq, d_k]  # 32 heads
K: [batch, 1, seq, d_k]          # 1 shared K
V: [batch, 1, seq, d_k]          # 1 shared V
```

</div>

**اثر:** ۳۲ برابر کاهش در حجم KV cache، با مقداری افت کیفیت.

### توجه کوئری گروه‌بندی‌شده (GQA - Grouped-Query Attention)

اشتراک‌گذاری K و V میان گروه‌هایی از هدهای Query:

<div dir="ltr">

```python
# GQA with 8 KV heads for 64 query heads (8:1 ratio)
Q: [batch, 64, seq, d_k]  # 64 query heads
K: [batch, 8, seq, d_k]   # 8 KV heads
V: [batch, 8, seq, d_k]   # 8 KV heads

# Each KV head serves 8 query heads
```

</div>

**اثر:** ۸ برابر کاهش در حجم KV cache با کمترین افت کیفیت.

**مدل‌های استفاده‌کننده از GQA:**
- مدل‌های Llama 2 70B و Llama 3.x 70B: دارای ۸ هد KV به ازای ۶۴ هد Query
- مدل Llama 3.1 405B: دارای ۸ هد KV به ازای ۱۲۸ هد Query
- مدل Llama 4 Maverick: دارای ۸ هد KV به ازای ۴۰ هد Query
- مدل Mistral 7B: دارای ۸ هد KV به ازای ۳۲ هد Query
- مدل Gemma: پیکربندی‌های گوناگون

### مقایسه

| نوع مکانیزم توجه | حجم KV Cache | کیفیت | مدل‌ها |
|-----------|----------|---------|--------|
| MHA | کامل | بهترین | GPT-3 |
| GQA | معمولاً ۱/۸ | نزدیک به بهترین | Llama 2 70B, Llama 3, Mistral |
| MQA | 1/n_heads | کاهش‌یافته | PaLM, Falcon |
| MLA | متغیر نهفته فشرده‌شده، چند درصد از MHA | هم‌تراز با MHA در آزمون‌های تجربی DeepSeek | خانواده DeepSeek-V2 و V3، مدل Kimi K2، Tencent Hy4 |

<a id="practical-implications"></a>

## پیامدهای عملی

### برای طراحی سیستم

۱. **موازنه میان اندازه دسته (Batch size) و کانتکست:**
   - کل حافظه GPU برابر است با: Model + KV cache * batch_size
   - کانتکست‌های طولانی‌تر به معنای اندازه‌های دسته کوچک‌تر هستند
   - مدل‌های مبتنی بر GQA می‌توانند به درخواست‌های هم‌زمان بیشتری پاسخ دهند

۲. **تخصیص بودجه تاخیر (Latency):**
   - محاسبات مکانیزم توجه از مرتبه O(n^2) است؛ الگوریتم Flash Attention حافظه آن را به O(n) تبدیل می‌کند، نه محاسبات آن را
   - مرحله Prefill (پردازش Prompt) متناسب با طول Prompt مقیاس می‌گیرد
   - مرحله Decode (تولید) متناسب با طول Tokenهای تولیدشده + طول Prompt مقیاس می‌گیرد

۳. **گلوگاه پهنای باند حافظه (Memory bandwidth bottleneck):**
   - تولید معمولاً محدود به حافظه (memory-bound) است
   - هر گام رمزگشایی (decode) مجدداً وزن‌ها (که در دسته‌های کوچک غالب است) و KV cache (که در کانتکست طولانی و دسته‌های بزرگ غالب است) را بازخوانی می‌کند
   - دسته‌های بزرگ‌تر هزینه خواندن وزن‌ها را سرشکن (amortize) می‌کنند؛ در حالی که خواندن KV با اضافه شدن هر درخواست افزایش می‌یابد

### مقایسه Prefill در برابر Decode

| فاز | الگوی محاسباتی | گلوگاه |
|-------|-----------------|------------|
| Prefill | پردازش تمام Tokenهای ورودی | محاسبات (هسته‌های GPU) |
| Decode | تولید یک Token در هر زمان | حافظه (پهنای باند) |

به همین دلیل است که TTFT (زمان تا دریافت اولین Token) و TPS (تعداد Token در ثانیه) به طور جداگانه اندازه‌گیری می‌شوند.

### مقیاس‌پذیری طول کانتکست

| کانتکست | محاسبات توجه | حافظه KV Cache در Llama 3.x 70B (با GQA و فرمت BF16) | ساختار مشابه با MHA کامل |
|---------|-------------------|-------------------------------------|--------------------------|
| 4K | خط مبنا (Baseline) | ۱.۳ گیگابایت | ۱۰.۷ گیگابایت |
| 8K | 4x | ۲.۷ گیگابایت | ۲۱.۵ گیگابایت |
| 32K | 64x | ۱۰.۷ گیگابایت | ۸۶ گیگابایت |
| 128K | 1024x | ۴۳ گیگابایت | ۳۴۴ گیگابایت |

کانتکست‌های طولانی نیازمند موارد زیر هستند:
- الگوریتم Flash Attention (کارآمد از نظر مصرف حافظه)
- استفاده از GQA، MQA یا MLA (برای KV cache کوچک‌تر)، یا یک معماری توجه هیبریدی
- کَش KV با دقت FP8 (که ارقام BF16 فوق را نصف می‌کند) و انتقال (offload) به DRAM میزبان (host)
- احتمالاً موازی‌سازی مدل (Model Parallelism)

## سوالات مصاحبه

### سوال: مکانیزم توجه را توضیح دهید و بگویید چرا مقیاس‌پذیری آن درجه دو (quadratically) است؟

**پاسخ قوی:**
مکانیزم توجه، تعاملات دو‌به‌دو میان تمام موقعیت‌ها را محاسبه می‌کند. برای n موقعیت:

۱. حاصل‌ضرب Q @ K^T یک ماتریس n × n از امتیازها تولید می‌کند
۲. هر امتیاز توجه یک حاصل‌ضرب داخلی (dot product) از یک query و یک key است
۳. در مجموع: n^2 حاصل‌ضرب داخلی

این محاسبه نسبت به طول توالی دارای مقیاس درجه دو است. برای 8K تا Token، این مقدار برابر با ۶۴ میلیون امتیاز دوبه‌دو به ازای هر لایه و هر هد است. برای 128K تا Token، این رقم به ۱۶ میلیارد می‌رسد.

مقیاس‌پذیری درجه دو طول کانتکست را محدود می‌کند. راهکارها عبارتند از:
- الگوریتم Flash Attention: محاسبات از مرتبه O(n^2) اما مصرف حافظه از مرتبه O(n)
- توجه تنک (Sparse attention): از مرتبه O(n) با توجه به زیرمجموعه‌ها
- توجه خطی (Linear attention): تقریب‌هایی با مرتبه O(n)
- مدل‌های هیبریدی: استفاده از لایه‌های خطی یا پنجره لغزان برای بخش اعظم عمق مدل، به همراه چند لایه توجه کامل یا تنک برای بازیابی دقیق (الگویی که اکثر پرچمداران متن‌باز سال ۲۰۲۶ با آن عرضه می‌شوند)

### سوال: حافظه KV cache چیست و چرا برای سرویس‌دهی حیاتی است؟

**پاسخ قوی:**
در طول تولید خودبازگشتی، ما در هر گام یک Token تولید می‌کنیم. بدون کَش‌سازی، هر Token جدید نیازمند محاسبه مجدد K و V برای تمام موقعیت‌های قبلی خواهد بود.

مکانیزم KV cache تانسورهای K و V موقعیت‌های قبلی را ذخیره می‌کند. به ازای هر Token جدید:
۱. محاسبه Q، K و V فقط برای موقعیت جدید
۲. الحاق (Append) مقادیر جدید K و V به کَش
۳. محاسبه توجه نسبت به کل K و V کَش‌شده

این امر پیچیدگی محاسباتی تصویرسازی (projection) به ازای هر Token را از O(n) به O(1) کاهش می‌دهد.

هزینه این کار در مصرف حافظه است: حجم KV cache به صورت خطی با طول توالی افزایش می‌یابد. برای مدل Llama 70B در کانتکست 8K با معماری GQA (شامل ۸ هد KV)، این مقدار به ازای هر درخواست حدود ۲.۷ گیگابایت است و در صورت استفاده از MHA کامل به حدود ۲۱ گیگابایت می‌رسید. در کانتکست 128K حتی با وجود GQA، این مقدار حدود ۴۳ گیگابایت است. این مسئله مستقیماً اندازه دسته (batch size) و توان عملیاتی (Throughput) را محدود می‌سازد.

روش‌های GQA و MQA با به اشتراک‌گذاری K و V میان هدهای query این حجم را کاهش می‌دهند؛ معماری MLA مقادیر K و V را در یک متغیر نهفته فشرده می‌کند؛ و استفاده از FP8 KV تعداد بایت‌ها را به نصف می‌رساند.

### سوال: روش‌های MHA، GQA و MQA را با یکدیگر مقایسه کنید.

**پاسخ قوی:**
| گونه | هدهای K و V | حجم KV Cache | کیفیت | مورد کاربرد |
|---------|-----------|----------|---------|----------|
| MHA | برابر با هدهای Q | کامل | بهترین | آموزش، کاربردهای حساس به کیفیت |
| GQA | کمتر از هدهای Q | کاهش‌یافته | نزدیک به MHA | سرویس‌دهی پروداکشن |
| MQA | ۱ | حداقل | کاهش‌یافته | محیط‌های با محدودیت شدید حافظه |

روش MHA: هر هد query دارای K و V اختصاصی خود است. بالاترین کیفیت اما بزرگ‌ترین حجم KV cache.

روش GQA: گروه‌هایی از هدهای query مقادیر K و V را به اشتراک می‌گذارند. مدل Llama 2 70B از ۸ هد KV برای ۶۴ هد query (نسبت ۸:۱) استفاده می‌کند؛ که کَش را ۸ برابر کوچک‌تر کرده و کمترین افت کیفیت را دارد.

روش MQA: تمام هدهای query یک جفت K و V مشترک دارند. حداکثر صرفه‌جویی در حافظه اما کاهش کیفیت محسوس. مورد استفاده در PaLM.

برای سرویس‌دهی، GQA بهترین موازنه است. این روش امکان استفاده از اندازه‌های دسته بزرگ‌تر (توان عملیاتی / Throughput بالاتر) را با کیفیتی تقریباً مشابه MHA فراهم می‌کند.

### سوال: الگوریتم Flash Attention چگونه به مصرف حافظه با مرتبه O(n) دست می‌یابد؟

**پاسخ قوی:**
مکانیزم توجه استاندارد ماتریس توجه n × n را به طور کامل در حافظه GPU شکل داده و ذخیره می‌کند (materialize). فلش اتنشن با اقدامات زیر از این کار جلوگیری می‌نماید:

۱. **کاشی‌کاری (Tiling):** پردازش بلوک‌هایی از Q و K که در حافظه روی تراشه SRAM جای می‌گیرند
۲. **سافت‌مکس برخط (Online softmax):** محاسبه تدریجی softmax بدون نیاز به ذخیره‌سازی تمام امتیازها
۳. **محاسبه مجدد (Recomputation):** در طول پاس پس‌انتشار (backward pass)، محاسبه مجدد توجه به جای بارگذاری مقادیر ذخیره‌شده

بینش کلیدی این است که حافظه SRAM روی تراشه یک رتبه بزرگی (order of magnitude) سریع‌تر از HBM است اما حجم بسیار اندکی دارد. ارقام مربوط به پردازنده A100 در مقاله FlashAttention عبارتند از: ۱۹۲ کیلوبایت SRAM به ازای هر SM (حدود ۲۰ مگابایت در مجموع ۱۰۸ تا SM) با سرعت تقریباً ۱۹ ترابایت بر ثانیه (19 TB/s)، در مقایسه با ۴۰ تا ۸۰ گیگابایت حافظه HBM با سرعت ۱.۵ تا ۲.۰ ترابایت بر ثانیه. فلش اتنشن با انجام محاسبات حسابی بیشتر در SRAM و کاهش خواندن/نوشتن در HBM، هم سریع‌تر عمل می‌کند و هم حافظه کمتری مصرف می‌نماید.

نتیجه این رویکرد، توجه دقیق (نه یک تقریب) با مصرف حافظه O(n) و افزایش سرعت ۲ تا ۴ برابری نسبت به توجه استاندارد در مقاله اصلی است. نسخه FlashAttention-3 معماری Hopper را هدف قرار می‌دهد و FlashAttention-4 پشتیبانی از Blackwell را اضافه می‌کند.

### سوال: چگونه اندازه KV cache را برای یک مدل متن‌باز جدید با وزن‌های باز در سال ۲۰۲۶ تخمین می‌زنید؟

**پاسخ قوی:**
تنها با فرمول‌های کتاب‌های درسی نمی‌توان این کار را انجام داد. فرمول `2 x layers x kv_heads x head_dim x bytes` فرض می‌کند که هر لایه مقادیر کامل K و V را برای تک‌تک Tokenها ذخیره می‌سازد؛ این فرض برای معماری‌های GQA مشابه Llama صادق است (۳۲۰ کیلوبایت به ازای هر Token برای یک مدل 70B در فرمت BF16)، اما برای پرچمداران متن‌باز کنونی صادق نیست:

- **لایه‌های هیبریدی (ترکیبی):** مدل MiMo-V2.6-Pro دارای ۶۰ لایه پنجره لغزان با پنجره ۱۲۸ تایی Token و ۱۰ لایه سراسری است، بنابراین تنها لایه‌های سراسری همگام با افزایش کانتکست رشد می‌کنند. مدل Qwen3.8-Flash-Next در سه لایه از هر چهار لایه خود، وضعیت توجه خطی با اندازه ثابت نگهداری می‌کند.
- **حافظه کش KV فشرده‌شده یا مشترک:** مدل DeepSeek V4.1-Flash مقادیر KV سراسری دیکودر را از حالت‌های انکودر تصویرسازی می‌کند و KV اصلی را با فرمت FP4 ذخیره می‌نماید که به ازای هر Token تنها ۸۹۰ بایت KV سراسری مصرف می‌کند (گزارش‌شده توسط DeepSeek)؛ یعنی بیش از ۳۰۰ برابر کمتر از رقم مربوط به Llama 70B. این مقدار شامل KV پنجره لغزان نمی‌شود که مقدار ثابتی به ازای هر درخواست بوده و به اندازه پنجره محدود است؛ بنابراین این اختلاف در کانتکست‌های طولانی به بیشترین حد خود می‌رسد.
- **دقت محاسباتی (Precision):** استفاده از FP8 KV حجم BF16 را نصف می‌کند؛ و FP4 با اعمال بررسی‌های کیفی، مجدداً آن را به نصف کاهش می‌دهد.

فرآیند من: خواندن فایل `config.json` (انواع لایه‌ها، اندازه‌های پنجره، هدهای KV یا ابعاد متغیر نهفته، نوع داده KV dtype)، استناد به عدد KV به ازای هر Token منتشرشده توسط ارائه‌دهنده در صورت وجود، و سپس اندازه‌گیری میزان مصرف واقعی کَش در موتور هدف با توزیع کانتکست واقعی من؛ زیرا پشتیبانی موتورها از چیدمان‌های کَش هیبریدی بسته به نسخه متفاوت است. ظرفیت نهایی از تقسیم (HBM منهای وزن‌های مدل) بر میزان KV به ازای هر درخواست در صدک ۹۵ام (P95) طول کانتکست، به علاوه هر سطح انتقالی (offload) به حافظه میزبان که موتور از آن پشتیبانی می‌کند، به دست می‌آید.
